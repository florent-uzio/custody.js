# What would owning the generator cost? (issue #316, map #314)

Question: inspect `openapi-typescript` 7.13.0 and the OpenAPI 3.0 features our bundled specs exercise; estimate effort and upkeep of (i) vendoring 7.13 into `scripts/` and (ii) writing a minimal generator that emits the current `paths` / `operations` / `components` shape.

Sources: `npm view openapi-typescript@7.13.0`, the installed package (`node_modules/openapi-typescript`: `package.json`, `src/`, `dist/`, `LICENSE`), `scripts/generate-custody-types/*.mjs`, and a scan of the bundled specs under `openapi/` (after `merge.mjs`, i.e. exactly what the generator is fed). The throwaway scripts were not committed.

## TL;DR

- Vendoring 7.13 is cheap (about 1 day) and removes the whole dependency tree: 33 transitive packages become 0 new ones (`typescript` is already a devDependency). The only real work is replacing the Redocly bundle/lint step, which is effectively a no-op for our input.
- Writing our own is feasible because the specs use a small, regular subset of OpenAPI 3.0. A naive 35-line emitter already reproduced 1025 of 1030 non-discriminator, non-`allOf` component schemas modulo redundant parentheses. The real work is discriminators, `paths`/`operations`, and JSDoc: estimate 600 to 900 LOC plus tests, about 3 to 5 days, and it is ours to maintain.
- Vendoring preserves the output shape byte for byte by construction. An own generator needs a reviewed semantic diff (which the map's acceptance bar requires anyway).

### What each runtime dependency is used for on our path

- `@redocly/openapi-core` (5.1 MB installed, 9 deps of its own): used only in `lib/redoc.ts` and `index.ts` to (a) parse the input, (b) `lintDocument` with the `minimal` ruleset plus an `operation-operationId-unique` error rule, and (c) `bundle({ dereference: false })` to resolve external `$ref`s. Our input is an in-memory object whose only `$ref`s are `#/components/schemas/*` (scan below), so (c) is the identity and (a) is a `JSON.parse` we already did. (b) is the only behavioural loss: duplicate-operationId and malformed-spec errors. A roughly 20 to 30 LOC check replaces it.
- `parse-json`: parses string input in `redoc.ts`; unused for object input.
- `ansi-colors`: colored log output (`utils.ts`); droppable.
- `change-case`: only in `components-object.ts`, behind the `rootTypes` option, which we do not set.
- `yargs-parser`, `supports-color`: CLI only (`bin/cli.js`); we use the programmatic API.
- `typescript`: the generator builds a TS AST with `ts.factory` (`lib/ts.ts`) and `astToString` prints it. This is the one dependency that cannot be dropped when vendoring.

### Options `generate.mjs` passes

None: `await openapiTS(merged)` with defaults, then `astToString(ast)`. Effective defaults (from `index.ts`): `additionalProperties=false`, `defaultNonNullable=true`, `alphabetize=false`, `enum=false` (string unions), `exportType=false` (interfaces), `immutable=false`, `rootTypes=false`, `propertiesRequiredByDefault=false`, `emptyObjectsUnknown=false`, `readWriteMarkers=false`, `makePathsEnum=false`, `generatePathParams=false`; `transform`, `postTransform`, `inject` unset. A large part of the 3855 LOC (option branches, `paths-enum`, `webhooks`, `rootTypes`, TS-enum output, `readWriteMarkers`, `excludeDeprecated`, ...) is therefore dead weight for us.

Output shape today (`src/models/custody-types.ts`, 23,759 lines; internal 7,683): `export interface paths`, `export type webhooks = Record<string, never>`, `export interface components { schemas: {...}; ... }`, `export type $defs = Record<string, never>`, `export interface operations`.

## 3. Cost of (i): vendor 7.13 into `scripts/`

What to vendor: upstream `src/` at the `v7.13.0` tag (TS, MIT) or the shipped `dist/*.mjs` (plain ESM JS with sourcemaps, no build step needed). Keep `LICENSE` and a header noting origin either way.

What can be dropped:

- `lib/redoc.ts` and every `@redocly/*` import: replace with a passthrough plus a small validator (version is `3.x`, `operationId` unique, every `$ref` resolves). About 30 LOC.
- `parse-json`, `ansi-colors`, `change-case`, `yargs-parser`, `supports-color`, `bin/cli.js`, unused option plumbing in `types.ts`, `paths-enum`, `webhooks-object` (emit the fixed line), the `rootTypes` branch of `components-object`.
- Kept after pruning: roughly 2,000 to 2,500 LOC (rough estimate: 3,855 minus redoc 164, CLI, unused option branches and types). `merge.mjs` and `capabilities.mjs` are untouched.

Effort: about 1 day. Copy, delete branches, replace `validateAndBundle`, swap the `openapiTS` import in `generate.mjs`, regenerate, and confirm `git diff --stat src/models/*.ts` is empty. Byte-identical output is achievable and is the strongest check possible since the code is the same.

Dependency result: 0 new runtime dependencies; still needs `typescript` (peer `^5.x`) for the AST factory and printer. Criterion 4 caveat: if the repo moves typecheck to TypeScript 7 native, the build script would need a `typescript@5` install (for example an npm alias) because 7.13's `lib/ts.ts` calls the TS compiler JS API. Whether TS 7 native offers an equivalent factory/printer API was not verified here and belongs to the `tsgo` ticket.

Ongoing maintenance: low in practice. Upstream is in maintenance mode (openapi-ts/openapi-typescript#2874), so there is little churn to track, and the dependency tree we would no longer receive advisories for is the tree we delete. Risks: (a) we own about 2k LOC of someone else's code, with no tests unless we also vendor upstream's (not inspected here); (b) a future Custody spec using a feature never exercised (`anyOf`, `readOnly`, numeric enums) hits upstream code paths that no longer get fixes; (c) validation regression if the 30 LOC replacement is too lax; (d) vendored code must be clearly separated from ours (own folder, excluded from oxlint/oxfmt).

## 4. Cost of (ii): write a minimal generator

Required output: the same `paths` / `operations` / `components` shape so the 45 consuming `src/` files compile with only mechanical changes.

### Proof (throwaway, not committed)

A 35-line string emitter for `components.schemas` handling `$ref`, enums, `oneOf`, arrays, primitives, `required`, `nullable`, and `additionalProperties`-as-schema was compared per schema against the real `custody-types.ts` (both printed through the TS printer without comments):

- 1174 public schemas. Skipped: 131 containing a `discriminator`, 12 with `allOf`, 1 other; 1030 attempted.
- 1003 identical; 1025 identical once redundant parentheses are ignored (a printer-level difference, trivial to match). The other 5 differ in one corner: a free-form `{}` as an `additionalProperties` value is `Record<string, never>` upstream but `Record<string, unknown>` in the proof.
- Not attempted: discriminators, `allOf`, `paths`, `operations`, JSDoc.

So about 88% of schemas are nearly free. The cost is in the remainder.

### Where the work is

| Piece                                                                                                                 | What upstream does                                                                                                                                                                                                                                                              | Rough LOC for us                                            |
| --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| Schema emitter (primitives, arrays, enums, objects, `oneOf`, `nullable`, `additionalProperties`, free-form objects)   | `schema-object.ts` core                                                                                                                                                                                                                                                         | 100 to 150                                                  |
| Discriminators with `mapping`                                                                                         | `scanDiscriminators` pre-pass mutates mapped child schemas to add a required literal/enum discriminator property (`utils.ts` `createDiscriminatorProperty`, `patchDiscriminatorEnum`, about 120 LOC); `schema-object.ts` wraps `allOf` members with `Omit<..., "propertyName">` | 120 to 180 (216 schemas across both surfaces; highest risk) |
| `allOf` (25 schemas), incl. interplay with discriminators                                                             | `schema-object.ts`                                                                                                                                                                                                                                                              | 40 to 60                                                    |
| `paths` interface (per-path method slots with `never`, `parameters` block)                                            | `paths-object.ts`, `path-item-object.ts`                                                                                                                                                                                                                                        | 60 to 80                                                    |
| `operations` (params, `requestBody`, `responses` incl. `default`, content types, headers, no-content)                 | `operation-object.ts`, `parameters-array.ts`, `response-object.ts`, `request-body-object.ts`, `responses-object.ts`, `header-object.ts`                                                                                                                                         | 150 to 220                                                  |
| JSDoc (description, `@deprecated`, `Format:`, `@default`, `@example`)                                                 | `ts.ts` `addJSDocComment`                                                                                                                                                                                                                                                       | 40 to 60                                                    |
| Scaffolding (`webhooks`, `$defs`, empty `components.*` slots) and validation (operationId uniqueness, ref resolution) | various                                                                                                                                                                                                                                                                         | 40 to 60                                                    |
| Tests (golden diff against current output, per-feature unit tests)                                                    |                                                                                                                                                                                                                                                                                 | 200 to 300                                                  |

Total: about 600 to 900 LOC of generator plus 200 to 300 of tests, roughly 3 to 5 days including the semantic-diff review the acceptance bar requires.

Printing choice: building a TS AST keeps `typescript` as a build dependency (same TS 7 caveat as vendoring). Emitting strings and formatting with oxfmt removes that dependency but changes whitespace and parenthesisation, so the diff versus the old files is noisy and review must be semantic, not textual.

### Risks and maintenance

- Discriminator semantics are the main fidelity risk: a wrong guess silently weakens narrowing on discriminated `oneOf` unions. Mitigation: golden comparison of every discriminated schema against current output.
- Optional/required and `nullable` subtleties: upstream `defaultNonNullable=true` treats a property with a `default` as non-optional in output; the 40 public `default`s need checking.
- A new Custody spec may introduce an unexercised keyword. The generator must fail loudly on unknown keywords (cheap to add) rather than guess.
- Ongoing ownership is 600 to 900 LOC of bespoke code with a small closed feature set and no external churn.

| Maintenance                 | frozen code, near zero                                          | small but ours; risk concentrated in discriminators |

## Implications for the map

- Both "own it" options remove the criterion 1 concerns (dependency count, maintainers, release cadence) at the cost of owning code. Vendoring is the lowest-risk path to a byte-identical `custody-types.ts`.
- Writing our own is credible because only a small OpenAPI subset is used (no `anyOf`, `readOnly`, external refs, parameter styles, cookie params, numeric enums), but it costs several times more; the extra effort mainly buys independence from the TypeScript compiler JS API.
- Any third-party replacement should be judged against the same inventory: discriminator with `mapping` on `oneOf` and `allOf`, string enums, `nullable`, `operationId`-less `paths` entries, and the `default` response code.
